# Compatibility and upstream port

`lapis-acp` is a derived work. Most of its design and a substantial part of its
logic come from the upstream `buzz-acp` crate in the `block/buzz` repository,
which is Apache-2.0. This chapter governs how that relationship stays auditable
so the port can be updated rather than rewritten when upstream moves.

Upstream source is never committed here. It is pinned by commit, materialized
into ignored scratch storage on demand, verified against recorded digests and
compared through a per-file disposition map. References are not runtime
dependencies.

## Requirements

| ID             | Requirement                                                                                                                                                           |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LAC-COMPAT-001 | The upstream port source MUST be pinned by repository, path and commit in `docs/upstream-lock.md` together with a per-file disposition map.                           |
| LAC-COMPAT-002 | Adopted upstream attribution MUST be recorded in `docs/licenses/NOTICE.md`, and upstream repository-level agent instructions MUST NOT be copied into this repository. |
| LAC-COMPAT-003 | Upstream drift MUST be detectable by a script that materializes the pinned source into ignored scratch storage and verifies recorded digests.                         |
| LAC-COMPAT-004 | The Rust toolchain MUST be pinned and formatting MUST be checked by both the normal and the specification check lanes.                                                |
| LAC-COMPAT-005 | Integration tests MUST reach a terminal outcome without a model provider, a network endpoint or a credential.                                                         |
| LAC-COMPAT-006 | Qualification against a real installed runner MUST be recorded separately and MUST NOT be inferred from fixture-peer tests.                                           |
| LAC-COMPAT-007 | Every disposition in the port map MUST be one of ported, ported-with-changes, dropped or not-ported, and a dropped region MUST name the reason.                       |

## Upstream lock

The pin is `block/buzz` crate `crates/buzz-acp` at commit
`2664d14316790a57ea44b3f97c57440b70e43436`, Apache-2.0, audited in
[the upstream lock record](../../docs/upstream-lock.md). Two files carry the
record and they have different authors. `docs/upstream/disposition.json` is
curated by hand and is the authority on intent: it names the pin, the owner
vocabulary, and a disposition and note for every upstream region.
`docs/upstream/lock.json` is generated by joining that map with observed SHA-256
digests, so a reviewer can see the exact bytes the port claims to derive from.

Because upstream concentrates logic in very large files and this repository
decomposes them under a counted-line budget, the map is recorded per region
rather than per whole file: a whole-file mapping would make every upstream
comparison a diff against a file that no longer exists here. Each region names
an owning crate or chapter drawn from a declared vocabulary, so a re-port has a
target and an invented owner fails validation.

The two files may not disagree. The lock validator rejects a digest that is not
64 lowercase hexadecimal characters, a region present in one file and absent
from the other, and a lock whose disposition or owner drifted from the curated
map, so regenerating the lock cannot quietly rewrite the port's intent.

`scripts/upstream-sync.mjs` has three modes. `--self-test` is a normal check
lane and never touches the network: it validates the pin and the map, and
reconciles them with the generated lock when one exists. `--write` and `--fetch`
are explicit opt-in network lanes. `--write` resolves the pinned crate tree,
downloads every region, computes digests and regenerates the lock. `--fetch`
re-downloads and reports drift. Both refuse to proceed when upstream holds a
region the curated map does not classify, or when the map classifies a region
upstream no longer has, so a new upstream file cannot enter the pin silently.

Materialized upstream source lands only in the ignored
`.local/upstream/<slug>@<commit>` subtree. It is never committed, never edited
in place and never referenced by a build. Drift is resolved by re-reviewing each
changed region against its owning module and updating its note, not by
regenerating the lock.

## Disposition

Every classified region carries exactly one disposition and the vocabulary is
closed. At the pinned commit the 40 regions divide into 1 ported, 18
ported-with-changes, 14 dropped and 7 not-ported.

| Upstream region                                            | Disposition                                             |
| ---------------------------------------------------------- | ------------------------------------------------------- |
| ACP client: framing, correlation, session methods          | ported-with-changes                                     |
| Turn pool, isolated execution, prompt framing              | ported-with-changes                                     |
| Shared runtime, pool lifecycle, task session model         | ported-with-changes                                     |
| One-shot task runner and task document contract            | ported-with-changes                                     |
| Deterministic ACP peer fixture                             | ported-with-changes                                     |
| Binary entry point                                         | ported                                                  |
| Session scoping                                            | ported-with-changes: one opaque caller-named scope      |
| Base prompt and standing instruction prose                 | ported-with-changes: rewritten without relay references |
| Relay intake, subscriptions, recovery, REST discovery      | dropped: Nostr intake                                   |
| Author gate, owner resolution, workflow provenance         | dropped: Nostr identity                                 |
| Git signing, credential helpers, ephemeral keyfile         | dropped: Nostr signing                                  |
| Memory fetch, observer publication, usage publication      | dropped: relay publication                              |
| Setup and onboarding mode                                  | dropped: relay onboarding                               |
| Channel and thread session models                          | dropped: relay conversation concepts                    |
| Inbound queue, batching, deduplication and replay          | not-ported: persistent transport                        |
| Channel history prompt projection                          | not-ported: persistent transport                        |
| Standing pool lifecycle tests and harness-specific prompts | not-ported: persistent transport                        |

A dropped region names the reason it was refused and has no owner. A not-ported
region names an owning crate and a deferred concern, and is a deliberate
deferral tracked in the ledger rather than an oversight.

A `ported-with-changes` note records what changed, not merely that something
did. The ACP client region is the clearest case: it is decomposed into twelve
bounded modules, its automatic approval of every permission request is replaced
by a caller-supplied decision that defaults to cancellation, and its
advertisement of terminal-native authentication and vendor notification
extensions is removed because this harness holds no credentials and publishes no
telemetry. Each of those is a boundary this repository holds, so it is recorded
in the port map where a re-port will surface it rather than left in a commit
message where it will not.

## Toolchain and dependency pins

The toolchain is pinned by `rust-toolchain.toml` with the cargo, clippy and
rustfmt components, so formatting and lint results are reproducible and the
pinned component is what the check lanes invoke. `Cargo.lock` is committed and
every cargo invocation in a check lane passes `--locked`, so a dependency change
is an explicit reviewed edit rather than a silent resolution.

Third-party crates come from the registry under normal semver ranges. Nothing is
vendored as committed source, and no dependency is patched, aliased or shimmed
to work around a defect; a defect is fixed in its owning repository.

## Test qualification

Two levels of qualification are kept distinct and neither substitutes for the
other.

The fixture peer is a deterministic scripted ACP agent. It answers the protocol
methods with canned frames and can be told to hang at startup, hang during
session creation, refuse, exceed a deadline or spawn a long-lived descendant. It
proves framing, deadlines, cancellation, cleanup, sanitization and exit codes
with no model provider, no network and no credential, which is why every
automated lane uses it.

The real installed runner is an actual agent adapter on the operator's machine.
It proves that the ported protocol surface matches what a shipping adapter
actually speaks, including capability negotiation and configuration options the
fixture only approximates. That qualification is recorded as its own ledger task
with its own evidence kind, and the progress checker refuses to mark it done on
fixture evidence. A passing fixture suite is not a claim about any real agent.
